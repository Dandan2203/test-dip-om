# Архітектура FinAgent

## Компоненти

FinAgent складається з чотирьох основних частин:

1. `frontend` — React-інтерфейс із формами, таблицями, графіками, дашбордом і AI-чатом.
2. `backend` — Go REST API з автентифікацією, бізнес-логікою та доступом до даних.
3. `financial-ai-agent` — окремий FastAPI-сервіс для роботи з Anthropic API.
4. PostgreSQL — сховище користувачів, категорій, транзакцій, цілей, історії чату, налаштувань та журналу дій.

Backend організований шарами `domain`, `usecase`, `repository`, `delivery/http`. Клієнти AI та Monobank відокремлені від основної бізнес-логіки.

## Потік звичайного запиту

Frontend надсилає JWT-запит до backend. HTTP-обробник перевіряє вхідні дані, usecase виконує правила предметної області, repository читає або змінює PostgreSQL, після чого backend повертає відповідь.

У запитах до користувацьких сутностей застосовується `userID`, тому транзакції, категорії та цілі перевіряються на належність користувачу.

## Потік AI-чату

1. Backend отримує повідомлення й формує обмежений контекст із транзакцій, категорій та цілей.
2. AI-сервіс викликає модель із набором інструментів.
3. Інструменти читання обчислюють баланс, найбільші категорії витрат, прогрес цілей або простий сценарій покупки.
4. Інструменти дій лише описують очікувану дію.
5. Backend зіставляє її з даними користувача та повертає картку підтвердження.
6. Лише після підтвердження backend змінює дані та записує дію для можливого скасування.

Це один AI-асистент із викликом інструментів моделі, а не мультиагентна система.

## Інші AI-функції

- `/categorize` пропонує категорію за описом транзакції, але поки не підключений до користувацького сценарію;
- `/audit` статистично визначає нетипові витрати й використовує модель для короткого пояснення;
- фінансові відповіді є загальними та не замінюють професійну пораду.

## Додаткові модулі

Monobank імпортує транзакції та курси валют. Налаштовуваний дашборд зберігає розташування віджетів. Eval-набір і CI підтримують розробку та перевірку, але не є основними функціями застосунку.

## Межі реалізації

- аномалії обчислюються за запитом, без фонового планувальника та сповіщень;
- сценарій «що, якби» моделює лише вплив покупки на поточний місячний баланс;
- чат використовує обмежений набір останніх транзакцій;
- рекомендації формуються в діалозі, окремого рекомендаційного алгоритму немає.
