# Метрики FinAgent — до/після рефакторингу

## Латентність (LLM-виклики на одне повідомлення чату)

| Сценарій | До (LangGraph router+ReAct) | Після (нативний tool-use) |
|---|---|---|
| Просте запитання (без інструментів) | ≥ 2 виклики (router + відповідь) | 1 виклик |
| Запит із read-tool (баланс, топ-витрати) | ≥ 3 виклики (router → ReAct → відповідь) | 2 виклики (tool-use → tool-result → відповідь) |
| Дія (create_transaction тощо) | ≥ 3 виклики + ручний JSON-парсинг | 1 виклик, типізована схема |
| Захоплення аномалій (`/audit`) | Окремий router-виклик + відповідь | Без змін (прямий виклик Claude) |

**Результат**: на типовому чат-повідомленні −1–2 LLM-виклики ≈ −300–600 мс за оцінкою, менший рахунок за токени.

## Точність інтентів

| Метрика | До | Після |
|---|---|---|
| Метод визначення інтенту | Окремий classifier-виклик (ненадійний — моделював один із 4 класів) | Детермінований: виведено з шляху tool-use (`simulate_purchase` → SCENARIO; інший read → FINANCIAL; action-tool → ACTION; без tools → GENERAL) |
| Залежність від тексту відповіді | Так (regex/ключові слова) | Ні |
| Хибні спрацьовування intent=ADVICE | Можливі (класифікатор міг помилитися) | Неможливі структурно (ADVICE — лише мітка на фронті для GENERAL + дисклеймер) |
| Eval-baseline (20 фраз, `eval/fixtures/intents.json`) | н/д | ≥ 85 % очікувано (залежить від Haiku 4.5) |

## Точність парсингу дій

| Метрика | До | Після |
|---|---|---|
| Метод парсингу | Ручний JSON-зріз тексту + список ключових слів для contribute/withdraw | Антропічний `tool_use` блок зі схемою — типізовано |
| Окремий параметр для contribute vs withdraw | Ні (один параметр `direction: in/out` + хардкод-список слів) | Так: окремі `contribute_goal` / `withdraw_goal` |
| Помилки парсингу при нестандартному тексті | Часті (regex fragile) | Структурно виключено |
| Eval-baseline (10 фраз, `eval/fixtures/actions.json`) | н/д | ≥ 80 % очікувано |

## Безпека: неавтентифіковані ендпоінти

| Ендпоінт | До | Після |
|---|---|---|
| AI-сервіс `POST /chat` | Відкритий назовні (порт 8000 опублікований) | Закритий (`expose` замість `ports`); перевірка `X-Internal-Token` |
| AI-сервіс `POST /categorize` | Відкритий | Закритий (той самий shared-secret) |
| AI-сервіс `POST /audit` | Відкритий | Закритий |
| `POST /api/chat` (бекенд) | Auth-middleware | Auth-middleware + rate-limit 1 req/s burst 5 |

## Комплаєнс: guardrail інвестиційних порад

| Рівень | До | Після |
|---|---|---|
| Системний промт | Відсутній / мінімальний | Явна заборона персональних порад + інструкція додавати дисклеймер |
| Детермінований дисклеймер у коді | Ні | Так: Python додає «Це освітня інформація, не індивідуальна інвестиційна порада» до будь-якої відповіді з фінансовою порадою (не покладаємось лише на модель) |
| Покриття | 0 % | 100 % відповідей, де модель дає пораду |

## Пояснення аномалій (`/audit`)

| Метрика | До | Після |
|---|---|---|
| Метод зіставлення пояснень | За номером рядка у відповіді Claude | За `transaction_id` у JSON-масиві |
| Зсув при нестандартній відповіді | Можливий (рядки збивалися) | Неможливий структурно |
| Формат відповіді Claude | Довільний текст | `[{"transaction_id": <id>, "reason": "..."}]` — примусово |
