# Eval-харнес FinAgent

Перевіряє дві речі:

1. **Точність інтентів** — для 20 фраз (`fixtures/intents.json`) порівнює очікуваний `intent` (FINANCIAL / SCENARIO / ACTION / GENERAL) із тим, що повертає AI-сервіс.
2. **Парсинг дій** — для 10 фраз (`fixtures/actions.json`) перевіряє, що модель вибрала правильний `action_type` і розпізнала ключові поля (сума, тип, ID тощо).

## Запуск

```bash
# AI-сервіс має бути запущений
docker compose up -d ai

# Встановити залежність (якщо не у venv проекту)
pip install requests

# Запустити
export INTERNAL_API_TOKEN=<ваш токен з .env>
python eval/run_eval.py
```

За замовчуванням хариться `http://localhost:8000`. Щоб вказати іншу адресу:

```bash
python eval/run_eval.py --url http://ai:8000
```

## Структура фікстур

### `fixtures/intents.json`
```json
[
  {"id": 1, "message": "Скільки я витратив цього місяця?", "expected_intent": "FINANCIAL"},
  ...
]
```

### `fixtures/actions.json`
```json
[
  {
    "id": 1,
    "message": "Додай витрату 500 грн на каву",
    "expected_action_type": "create_transaction",
    "expected_fields": {"amount": 500, "transaction_type": "expense"}
  },
  ...
]
```

`expected_fields` — часткова перевірка: лише перелічені поля порівнюються; відсутні в очікуванні — ігноруються. Числа порівнюються з допуском ±0.5 (для округлень).

## Контекст запитів

Усі виклики надсилають однаковий зразковий контекст (7 транзакцій, 3 цілі, 5 категорій) — визначено у `run_eval.py::SAMPLE_CONTEXT`. Завдяки фіксованому контексту результати відтворювані між запусками.

## Додавання тест-кейсів

Відредагуйте `fixtures/intents.json` або `fixtures/actions.json` — формат JSON-масиву, поля описано вище. Якщо тестовий сценарій потребує специфічних сутностей (наприклад конкретний `transaction_id`), переконайтеся, що ці сутності є у `SAMPLE_CONTEXT`.
