# FinAgent

## Project description

FinAgent — прототип вебзастосунку для обліку особистих фінансів, розроблений як бакалаврська робота. Застосунок поєднує звичайний фінансовий облік із ШІ-асистентом.

## Main functionality

- реєстрація, вхід і редагування профілю;
- створення, редагування та видалення транзакцій;
- фільтрація, пагінація та CSV-експорт транзакцій;
- системні та користувацькі категорії;
- дашборд, статистика доходів і витрат та графіки;
- фінансові цілі й відстеження прогресу;
- ШІ-чат про доступні фінансові дані;
- прості сценарії впливу покупки на місячний баланс;
- загальні фінансові пояснення та пропозиції;
- показ нетипових витрат.

## Additional modules

- імпорт транзакцій і курси валют Monobank;
- налаштування розташування віджетів дашборда;
- окремий endpoint ШІ-категоризації, не підключений до інтерфейсу;
- eval-скрипти та CI-конфігурації.

## Architecture

- `frontend` — користувацький інтерфейс на React;
- `backend` — REST API та бізнес-логіка на Go;
- `financial-ai-agent` — FastAPI-сервіс для роботи з моделлю;
- PostgreSQL — база даних.

ШІ-сервіс не змінює базу даних напряму. Дії, що змінюють дані, перевіряє та виконує backend після підтвердження користувача.

Детальніше: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Фактичний стан функцій: [docs/FEATURE_AUDIT.md](docs/FEATURE_AUDIT.md).

## Technologies

Go, Gin, PostgreSQL, Python, FastAPI, Anthropic API, React, TypeScript, Vite, Docker Compose.

## Running locally

```bash
cp .env.example .env
# заповнити значення у .env
docker compose up -d --build
```

Інтерфейс доступний на `http://localhost`, backend API — на `http://localhost:8080`.

## Testing

```bash
docker compose config

cd backend
go test ./...

cd ../financial-ai-agent
python -m pytest tests -v

cd ../frontend
npm run lint
npm run build
```

## Implementation limits

- Це прототип бакалаврської роботи, а не готова комерційна система.
- ШІ-асистент не є професійним фінансовим радником; його пропозиції мають загальний характер.
- Усі дії ШІ-асистента, що змінюють дані, потребують підтвердження користувача.
- Нетипові витрати показуються в системі; фонових push- або email-сповіщень немає.
- Сценарій «що, якби» виконує простий розрахунок, а не фінансовий прогноз.
- Monobank, налаштування дашборда, ШІ-категоризація, eval і CI не потрібні для основного сценарію.
